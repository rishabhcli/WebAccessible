# Beta Fund Delivery Contract

## Role

Beta Fund is the program sponsor context for WebAccessible's delivery. Its role is accurately represented through clear credit, a concise sponsor-aware story, and a submission-ready evidence package. It is not a runtime dependency and must not be described as one.

## Deliverables

- Credit Beta Fund in the project framing, demo material, and submission copy.
- Use the three-minute demo sequence from the spec: real cold run, readable skill, real warm replay, Snowflake cost proof, and cross-user data-set framing.
- Keep the delivery checklist aligned to the stated hard submission and presentation deadline.
- Record a backup video of the same genuine user-control flow that is demonstrated live.
- Provide an accurate sponsor narrative:
  - Snowflake records real sessions and proves cost collapse.
  - EverOS turns a teach run into persistent, readable replay memory.
  - Beta Fund enables the event context in which the solution is being delivered.

## Evidence package

Before submission, retain:

- The final three-minute script and rehearsal checklist.
- A dated live-demo verification record: demo target, fallback target, Snowflake query evidence, EverOS Case/Skill evidence, and any provider readiness results.
- Backup video location and capture date.
- Project description with sponsor credits that match the implemented live paths.

## Accuracy rules

- Do not state that any sponsor is integrated based only on documentation, credentials, SDK imports, local fixtures, or planned architecture.
- Do not call the product autonomous. Margaret makes every click and submit action.
- Do not claim that the product stores or handles passwords.
- Do not describe a billing estimate, an empty dashboard, or a mocked memory object as real sponsor evidence.
